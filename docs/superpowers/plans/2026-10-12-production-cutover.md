# План переезда ayprom-gidravlika.kg с Vercel на Cloudflare (боевой запуск)

**Дата:** 2026-10-12 · **Статус:** на утверждении у владельца · **Ничего из этого плана ещё не выполнено на боевом сайте.**

Что уже готово и проверено на тестовой копии (staging): админка на Cloudflare (все разделы), очередь фото на GitHub Actions,
публикация сайта после правки (около 3 минут от правки до сайта), смена пароля, импорт CSV, журнал, «Спецтехника».
Этот план описывает, как перенести всё это на настоящий сайт безопасно и обратимо.

## 0. Что я узнал о боевой инфраструктуре (только чтение)

| Что | Факт |
|---|---|
| Домен | `ayprom-gidravlika.kg`, серверы имён (DNS) уже на Cloudflare, зона в вашем аккаунте Cloudflare |
| Сайт сейчас | Отдаёт Vercel напрямую (в ответе `Server: Vercel`, значит запись DNS «серая», без прокси Cloudflare) |
| Главный адрес | `www.ayprom-gidravlika.kg` (адрес без `www` Vercel перенаправляет на `www` кодом 308) |
| Фото и видео | `media.ayprom-gidravlika.kg` через Cloudflare R2, бакет `ayprom-media-production` — уже на Cloudflare, переносить не нужно |
| База | Supabase (боевой проект) — остаётся как есть |
| Vercel-зависимости в коде | `@vercel/speed-insights` (аналитика скорости), cron очистки временных фото, автодеплой из `main` |
| Мой Cloudflare-токен | Видит только Workers и R2, **не видит DNS и маршруты зоны** — это правильно, расширять его без вашего решения я не буду |

## 1. Главный принцип

Vercel остаётся включённым и готовым принять трафик обратно на всё время переезда и ещё минимум 30 дней после. Базу и фото не откатываем автоматически;
все изменения базы только добавляющие (старый сайт на Vercel с ними продолжает работать).

### Этап E. Переключение домена (окно 30–60 минут, вечер по Бишкеку)

Перед окном: вы предупреждаете всех, кто правит каталог: «в это время не править». Резервная копия базы свежая.

| № | Шаг | Кто | Ваше «да» |
|---|---|---|---|
| E1 | Финальная публикация из боевой базы, проверка на закрытом адресе | я | да |
| E2 | В Cloudflare (зона `ayprom-gidravlika.kg`): запись `www` переключается с «серой» на «оранжевую» (через Cloudflare). Vercel остаётся источником, сайт пока работает как раньше | **вы или я с временным токеном** | **да** |
| E3 | Правила маршрутов для `www`: `/admin*` и `/api/admin/*` → Worker админки; всё остальное → публичный Worker. Адрес без `www` → перенаправление на `www` (как сейчас делает Vercel) | вы или я | **да** |
| E4 | Проверка на реальном адресе: главная, каталог, карточка товара, поиск, `sitemap.xml`, `robots.txt`, `media.`, вход в админку, правка → публикация, фото | я | — |
| E5 | Проверка через поисковую консоль: sitemap читается, ответ на проверку нескольких адресов | я | — |

**Как откатиться за 1–2 минуты:** удалить два правила маршрутов (E3). Трафик сразу уйдёт на Vercel (через Cloudflare), затем вернуть запись `www` на «серую». Ничего в базе откатывать не нужно.
Автоматический триггер отката: массовые 5xx/1102, не работает вход или сохранение товара, товар не появился на сайте за 10 минут, фото отдаёт 404/403.

Маршруты через Cloudflare Worker Routes выбраны потому, что публичные страницы отдаются как обычные файлы без запуска кода, поэтому суточный лимит 100 000 запусков Worker на бесплатном тарифе нужен только админке и поиску.

## 3. Что может пойти не так

| Риск | Защита |
|---|---|
| Бесплатный лимит процессора Cloudflare (10 мс) на входе и тяжёлых действиях | Замер в D5 до переключения; на staging 50 из 50 запросов прошли; если на боевом упадёт — решаем до окна, а не во время |
| Слияние в `main` само выкладывает Vercel | Превью проверяется заранее, слияние — отдельное «да» |
| Две админки пишут в одну базу (старая на Vercel и новая) | После переключения старой не пользуются; Vercel-адрес держим только как запасной выход |
| Новый хеш пароля несовместим со старым кодом | На боевом сайте записи пароля в базе нет (вы не меняли), вход идёт по паролю из настроек; пароль не менять до конца переезда |
| Публикация не успевает / падает | Показываем ошибку и кнопку «Повторить»; старая версия сайта остаётся |
| Фото-обработчик исчерпал бесплатные минуты GitHub | Репозиторий публичный, минуты безлимитны; следим за очередью |
| Неточное совпадение с Vercel (SEO, адреса) | Автоматическое сравнение в D3 до переключения |

## 5. Решения, которые нужны от вас

1. **Окно переключения:** какой день и время (рекомендую вечер будней по Бишкеку, когда правят меньше всего).
2. **Кто нажимает в Cloudflare** на этапе E: вы сами по моей пошаговой инструкции, или вы создаёте временный токен с правами на DNS и маршруты зоны, а я делаю и сразу его отзываю.
3. **Сессии админки:** оставить прежний секрет (никого не выбросит из админки) или заменить (один раз войти заново). Рекомендую заменить.
4. **Аналитика скорости:** убрать или подключить бесплатную Cloudflare Web Analytics.
5. **Кто пользуется админкой** помимо вас (нужно ли предупредить).
