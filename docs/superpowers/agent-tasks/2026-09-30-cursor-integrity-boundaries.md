## Два воспроизведённых замечания Codex

1. `walkPackage` исключает `package-manifest.json` до проверки байтовых лимитов. Затем verifier читает его целиком. В диагностическом тесте lstat сообщал размер 25 МиБ + 1, readFileSync возвращал валидный JSON с реальным inventory: результат `{ok:true}`, чтение состоялось. Сам manifest не должен входить в собственный SHA-256, но это НЕ освобождает его от ограничений чтения. Кроме того, preview-runtime читает manifest/config до запуска verifier: ограничение нужно поставить перед этими первоначальными чтениями тоже.
2. Исключение чтения worker.js из `collectPackageInventory` выходит наружу без безопасного code/rule, сохраняя исходный текст. CLI также не имеет защитной границы исключений. Воспроизведено подстановкой readFileSync, бросающей фиктивную чувствительную строку. I/O-сбой должен дать фиксированный отказ, не исходное исключение/stack/path.
