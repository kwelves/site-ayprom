## 2. Транспорт активации/отката (Task 3)

`createWranglerReleasePort` (`wrangler-inactive-port.ts`). Команды сверены с
`wrangler versions deploy --help` установленной версии 4.135.0: активация и откат —
`versions deploy <id>@100 --yes --message ... --config ...`. Порт:
- активирует только версию, которую сам загрузил; каждая операция выполняется один раз;
- не принимает ответ на веру: `deployment_id` из выходного файла сверяется со
  списком `deployments list`; расхождение = «неизвестно» для coordinator;
- токен только в окружении дочернего процесса, не в аргументах/конфиге;
- прежний `createWranglerInactivePort` по-прежнему не умеет активировать.

TDD: RED 11 failed / 1 passed (функции не было) → GREEN 12 passed (+21 прежних).
Проверено только поддельным запуском команд. Wrangler не даёт условной
(compare-and-swap) активации, поэтому защита от параллельных ручных действий в
панели Cloudflare остаётся ограничением: перед настоящим выпуском нужен единый
журнал и запрет ручных деплоев на время выпуска. Формат вывода `version-deploy`
взят из исходников установленного Wrangler (`version_traffic` у него сериализуется
как `{}`, поэтому порт на него не опирается); живой вывод ещё не наблюдался.
