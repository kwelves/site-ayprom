# Сквозная локальная проверка фото (2026-10-03)

Статус: **локальный тест связки, не production gate**. Код сайта не менялся; добавлен только тест.

`tests/cloudflare-photo-local-flow.test.ts` соединяет уже существующие реальные модули: закрытые RPC-порты очереди, Node/Sharp-обработчик и R2 S3-адаптер с настоящим `S3Client`. Вместо Supabase/PostgREST и Cloudflare R2 используются два локальных HTTP-сервера с фиктивными ключами. Настоящий JPEG проходит через Sharp. Успешный сценарий проверяет порядок `claim → GET private staging → PUT/HEAD трёх public files → finish`, отсутствие записи финальных файлов в закрытый staging и пустую очередь после публикации.

Два отрицательных сценария доказывают отсутствие публикации при повреждённом исходнике и при неверной контрольной сумме, которую возвращает `HEAD` публичного файла. В обоих случаях `finish` не вызывается, аренда возвращается через `fail`.

Целевые тесты: 3/3; `npm run check`: код 0, 1696 тестов прошли, 4 пропущены, lint/typecheck/colors чистые. Сообщение jsdom о неподдерживаемой навигации не уронило тесты. Это обнаруживает ошибки стыка модулей, но фикстуры не воспроизводят транзакции настоящей базы, поведение настоящего R2 или лимиты хостинга. Следующий обязательный шаг остаётся прежним: применить итоговую SQL-миграцию к изолированной локальной базе, затем пройти flow на test R2 buckets без затрагивания production.
