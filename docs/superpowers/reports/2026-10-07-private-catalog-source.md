# Редактируемый каталог закрыт от прямого публичного чтения — локальный gate

## Итог

В локальной миграции `anon` и `authenticated` больше не читают напрямую 11
редактируемых таблиц каталога. Публичный поиск и чтение документа продолжают
работать через опубликованный выпуск; неподтверждённая правка исходной строки
не появляется в ответе. Приватный `service_role` сохраняет доступ для админки
и сборщика. Миграция **не применена в production**.

`supabase/schemas/prod.sql` теперь отзывает права и у `PUBLIC`, чтобы
унаследованное разрешение не стало обходом. Изменение оформлено отдельной
миграцией `20261007120445_private_catalog_source.sql`; в ней только `REVOKE`
для 11 таблиц, без удаления данных, таблиц, функций или широких `GRANT`.
Путь декларативной схемы в `supabase/config.toml` указан явно для безопасного
локального `supabase db schema declarative sync --no-apply`.

## Граница безопасности и следующий gate

Это доказательство только для изолированного локального Supabase и локального
workerd. `--pinned-build` проверяет готовые HTML/ссылки и Worker, но не
управляет настоящим браузером. Имеющийся `local-browser-probe.mjs` использует
активный неприкреплённый поиск и уже работающую общую БД; применять его к
новому pinned-пакету без адаптации было бы ложным доказательством. Для
полноценного браузерного gate нужен отдельный pinned-browser probe на том же
выпуске и в живом изолированном стеке.

Нельзя применять эту SQL-миграцию в production до публикации совместимого
legacy Next/Vercel-кода и проверки первого опубликованного выпуска. Никаких
push, deploy, DNS, Cloudflare account, production Supabase или R2 действий
не выполнялось.

ECC применён как рабочий процесс: RED → GREEN, проверка прав доступа и
повторный полный прогон. Проектный браузерный навык прочитан; его текущий
сценарий не подходит для pinned-режима, поэтому браузерный результат не
заявляется.
