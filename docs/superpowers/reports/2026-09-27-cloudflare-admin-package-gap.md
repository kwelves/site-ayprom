# Граница текущего пакета: админка отсутствует — 2026-09-27

Проверка выполнена на локальном пакете `dist/worker-packages/fresh-20260927-a8afa5c8` из commit `ae6854ce4abdc41eec2da8cfdb633850dc4b29d9`. Никаких login-попыток, операций с базой, push или deploy не было. Для запуска workerd использовался заведомо неработающий loopback upstream; проверялись только HTTP-статусы локального пакета.

## Факты

- В готовом `site/` нет каталога `admin`; `route-manifest.json` содержит только публичные маршруты.
- Локальный workerd этого пакета ответил `404` на `/admin` и `404` на `/admin/login`. `/api/health` ответил `200` в том же запуске.
- Исторические `307` и `200` для админки в реестре относились к эксперименту с полным vinext runtime. Он не выбран как production-основа, поэтому эти результаты не проходят ADM-01/ADM-02 для нынешнего пакета.
- Существующая Next-страница входа использует Server Action `login` из `src/lib/admin/actions.ts`. Копирование её HTML в Static Assets само по себе не перенесёт выполнение входа в Worker.
- Фактический текущий fallback в `src/lib/admin/credentials.ts` проверяет `ADMIN_PASSWORD`, если строка `admin_credentials` отсутствует. Следовательно, фазу auth нельзя строить на предположении, что production уже перешёл на пароль только в таблице.

## Следующий локальный срез

До удалённого staging отдельно спроектировать и проверить контракт статической оболочки `/admin`, маршрутизацию и защищённый вход через thin Worker. Начать с тестового, не production окружения: анонимный `/admin` не раскрывает защищённые данные; login/logout, rate limit, cookie, CSRF/Origin и инвалидирование сессий сохраняют legacy-поведение; публичный ключ не превращается в service-role. Выбор удалённого password verifier и изменение действующего Vercel login — отдельное архитектурное решение, не часть этой проверки.

До выполнения этого среза пакет остаётся диагностическим и непригоден для cutover, даже если его публичные страницы проходят локальные проверки.
