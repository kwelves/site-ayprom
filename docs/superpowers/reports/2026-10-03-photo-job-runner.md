# Local photo-job runner boundary (2026-10-03)

Status: **partial, local only**. This Node-only module is not imported by the Cloudflare request Worker or connected to live admin routes, Supabase or R2.

`src/cloudflare/media/product-photo-job-runner.mjs` consumes one already claimed database job. It rejects malformed job identity and source keys before I/O, reads the private staged bytes through a supplied storage port, verifies size and SHA-256, runs the existing Sharp processor, and prepares master/thumbnail/gallery. Each final object is conditionally created and then checked via the storage port for expected size, hash and MIME type. Only after all three checks does it call the database-finalize port with a body-free receipt. A retry can reuse matching immutable objects; it never overwrites or deletes them. Errors have fixed codes without object paths or storage/DB error text, and a failed run asks the job port to release/retry its lease. If finalization committed but its response was lost, a failed lease release is ignored so the database remains authoritative.

The next steps are an S3/R2 adapter with conditional writes and bounded reads, a Supabase RPC adapter, lease renewal or bounded processing time, private receipt and staging cleanup with reconciliation, and end-to-end checks against a separate test R2 bucket and isolated database. The existing Vercel photo flow remains unchanged. No remote service or production data was modified.
