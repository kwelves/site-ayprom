## Что сделано

После сборки HTML, CSS и метаданных producer может скопировать в `staging/site` только те файлы из `public/`, которые реально упомянуты и которые Git уже отслеживает (`git ls-files -- public`). Широкое копирование `public/` не делается. Без флага `--public-repo` прежний fixture-режим не меняется.

Ссылки берутся из атрибутов HTML, включая `srcset`, из CSS `url(...)` и из строк метаданных. Обычные страницы каталога, `/api/*`, `/_next/*` и чужие адреса (R2, Supabase и другие хосты) не считаются файлами `public/`. Адрес того же сайта обрабатывается как локальный путь. Query и hash отбрасываются.

Неотслеживаемый файл и отсутствующий файл дают явную ошибку и не копируются. Подозрительный путь (traversal, закодированный traversal, имя устройства Windows, junction/symlink) отклоняется до чтения цели. Совпадение с уже записанным HTML или `_next/static` тоже отклоняется, файл страницы не перезаписывается. В отчёте скопированные файлы идут по пути, с байтами, SHA-256 и общей суммой.

## Команда

```powershell
node scripts/cloudflare/static-producer-fixture.mjs --public-repo <каталог-git>
```

Без `--public-repo` команда как раньше копирует только документы fixture-сервера.

## Дополнение: общий лимит и meta refresh

Итоговая `validateArtifactPolicy` считает вместе документы crawl, `.next/static` и скопированные public-файлы. Граница 20 000 файлов проверяется на этом общем списке, без создания десятков тысяч файлов на диске. Ровно 20 000 проходят, 20 001 отклоняется.

`<meta http-equiv="refresh" content="1;url=/admin/products">` больше не считается ссылкой на файл в `public/`. `<meta property="og:image" content="/images/logo.svg">` по-прежнему копируется, если файл отслеживается Git.

## Что ещё мешает полному статическому сайту

- Нет настоящего `next build` / `next start`: страницы отдаёт fixture-сервер.
- Нет клиентского поиска, `_headers`, `_redirects` и каталожных данных для поиска.
- Нет браузерной проверки и проверки на workerd всего сайта.
- Подмена каталога junction уже после проверки и до чтения по-прежнему не закрыта.
- `dist/site` по-прежнему не обновляется этим этапом.
