# Полный справочник для импорта при росте каталога

Локальная подготовка миграции, ветка `codex/cloudflare-integration`, исходный HEAD `4f5ffc5`.

## Дефект и изменение

`loadCatalogReference()` читал пять таблиц одним запросом на каждую и отбрасывал ошибки. При `max_rows=1000` товар за первой тысячей не сопоставлялся по артикулу, занятый slug мог повторно выбираться для нового товара, а существующие категории/бренды считались неизвестными. При сбое базы commit мог продолжить работу с неполными данными.

Теперь каждая таблица читается порциями по 500 строк с уникальной сортировкой: `id` для подкатегорий, `slug` для остальных таблиц. Ошибка любой страницы прекращает импорт до вызова записывающего RPC. Backend-ошибка не передаётся пользователю. Проверка сессии остаётся перед чтением справочников; commit повторно разбирает исходный CSV.

Исправлена нынешняя Next-реализация импорта, которую предстоит адаптировать для Worker. Это не перенос раздела импорта на Cloudflare. SQL, production и другие worktrees не менялись.

## Проверки

- RED: 9 из 10 новых тестов упали на реальных неверных результатах: потерянное сопоставление по артикулу, повторный slug, неизвестная категория, продолжение после ошибок. Проверка авторизации уже проходила.
- Первый GREEN: 25/25 в четырёх файлах импорта.
- Добавлены проверки, что commit передаёт существующий slug из поздней страницы в RPC, а ровно 1000 строк завершаются пустой последней страницей.
- Тесты используют настоящий `supabase-js` query builder и CSV-парсер; HTTP-ответы подставлены. Они проверяют фактические offset/limit/order и результат импорта, но не представляют собой проверку настоящего PostgREST с 1001 строкой.
- Финальный `npm run check`: exit 0, 186 файлов passed / 1 skipped; 1654 теста passed / 4 skipped. В выводе остались прежние сообщения jsdom о неподдерживаемой навигации, которые сами по себе не подтверждают переход в настоящем браузере.
- `node scripts/cloudflare/local-publication-revision-smoke.mjs`: exit 0, 14/14 проверок; настоящий `next build`, 124/124 страниц crawl, Chromium 42/42, ошибок страниц/HTTP и неперехваченных prefetch — 0. Собственный временный Supabase остановлен и удалён (`cleanup:true`); общий стек не менялся. Этот прогон проверяет сборку и публичный сайт, не страницу импорта.
- Артефакт: `dist/staging/20261003T082355Z-3db84919`, diagnostic-only, исходный HEAD `4f5ffc5` плюс незакоммиченная правка импорта; это не release artifact финального commit.
- `git diff --check` — exit 0; Graphify обновлён: 4450 узлов / 8953 ребра. Остались прежние предупреждения о пяти JSON-файлах без узлов и переименовании сообществ графа.

## Границы

Порции не являются единым транзакционным снимком: параллельное изменение справочников между запросами остаётся отдельным вопросом для полной схемы импорта. Исправление рассчитано на текущий `max_rows=1000`; серверный предел ниже 500 потребует дополнительного контракта. Остальные запросы из DATA-01 и перенос import UI/API ещё не закрыты.

Документация: [Supabase range](https://supabase.com/docs/reference/javascript/using-modifiers-range) требует порядка и включает обе границы диапазона. Прочитана установленная документация Next `use-server.md`.
