# Защищённый список товаров: локальный Cloudflare admin-preview

Дата: 2026-09-30. Ветка: `codex/cloudflare-integration`.

Только локальная работа; push, deploy, DNS и production-изменений не было.

## Результат и границы

- `GET /api/admin/products`: защищённая JSON-страница из 50 товаров с точным количеством, поиском по названию/артикулу и стабильным порядком `order.asc,id.asc`.
- `GET /admin/products`: минимальная русскоязычная таблица, поиск, предыдущая/следующая страница и выход. Работает без JavaScript. Это диагностический интерфейс чтения, не перенос всей production-админки.
- Повторно используется чистый `getAdminProductQueryPlan` из legacy-кода. Next/Vercel adapter и публичный `search_catalog_products` RPC не менялись.
- Приватный ключ используется только внутри Worker для защищённого чтения, после проверки HMAC-сессии и её текущей версии. Публичный поиск продолжает использовать публичный ключ; черновики туда не попадают.
- Гость API получает 401; HTML-страница отправляет на вход. Поддельная, истёкшая или отозванная сессия не допускает чтения товаров. Ошибка backend не раскрывает детали. `POST`, `PATCH`, `DELETE` запрещены (405); записи данных этот API не делает.
- Ограничены `q` (200 символов), `page` (целое 1–100000), количество строк (50), размер backend JSON (1 MiB) и время запроса (10 секунд). Повторные `q`/`page` отклоняются. Ответы `no-store`; HTML дополнительно `noindex` и CSP без скриптов. Текст товаров и запроса экранируется.

## TDD и найденная runtime-проблема

Первые тесты защищённых маршрутов падали на прежнем 404/отсутствующем reader. После реализации целевые наборы прошли. Дополнительный RED на границе `offset === total` выявил ошибку проверки 416; условие исправлено на `offset >= total`.

Настоящий packaged smoke сначала возвращал 503 на первой странице товаров, хотя прямой ответ собственной тестовой Supabase был корректным (206, 50 строк, total 51). Причина: закреплённый локальный workerd отвергал параметр `redirect: "error"` до отправки HTTP-запроса. Это поведение конкретного локального runtime, а не утверждение обо всех версиях Cloudflare.

Добавлен отдельный regression-тест с настоящим workerd и loopback HTTP backend. Используется `redirect: "manual"` с отказом при redirect-ответе. Тест подтверждает успешное защищённое чтение и отсутствие запроса к redirect destination: приватные заголовки не пересылаются туда. Ошибки логируются только статическим кодом/этапом, без ключей, запросов или backend payload.
