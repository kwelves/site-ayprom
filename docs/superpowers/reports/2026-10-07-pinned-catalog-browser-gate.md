# Браузерная проверка локального опубликованного выпуска

## Результат

Полная локальная сборка каталога теперь считается успешной только после
проверки её упакованного Worker и статических страниц в настоящем Chromium.
Браузер ищет товар, открывает страницу товара через видимую фотографию
карточки, повторно открывает поиск по прямому URL и проверяет пустую выдачу.
Запросы к внешним адресам блокируются. Публичный ответ не должен содержать
служебный пропуск выпуска. Проверка не меняет сам пакет и не публикует его.

## TDD и проверки

- RED: новый браузерный тест сначала не импортировался — модуля probe не было.
  После реализации 3/3 теста прошли, включая отказ при отсутствии запроса API
  и при попадании служебного пропуска в ответ.

  сборку, а не просто записывает отдельный отчёт.

  фотография перекрывает растянутую ссылку карточки. Probe исправлен на
  видимый клик по фотографии. Следующий прогон: `pinnedBuild.ok:true`,
  `productionReady:false`; 82 SQL-теста выпуска, 28 HTTP-проверок,
  14 проверок capture, реальный Next build/crawl, локальный Worker и браузер.
- Целевые тесты браузера, пакета и сборщика: 46/46. `npm run check`: exit 0;
  lint, typecheck, check:colors (316 файлов), 211 файлов тестов прошли,

  `ready:true`, `productionReady:false`.

## Границы

Проверен один продукт и базовый поиск в изолированном локальном Supabase, не
все маршруты или production-данные. Полный браузерный gate старого smoke для
всех семейств каталога ещё требует привязки к тому же выпуску. Следующий
этап — сборка кандидата выпуска и проверка его согласованности при
параллельной правке. Удалённые Cloudflare, DNS, production Supabase и R2 не
затрагивались. Push/deploy не выполнялись.

Использованы проектный браузерный навык и настроенные для AYPROM ECC TDD,
security-review и verification-loop. Отдельный процент покрытия не измерялся:
в проекте нет настроенного coverage-gate.
