# Локальная проверка бесплатного пути для входа в Cloudflare-админку

Дата: 2026-10-01. Ветка: `codex/cloudflare-integration`. Это локальная подготовка, не изменение работающего сайта.

## Решение

Сохраняется нынешняя модель AYPROM: `ADMIN_PASSWORD`, пока строка `admin_credentials` пуста; затем PBKDF2-SHA256 с 600 000 итераций и версия учётных данных в строке. Старые сессии отклоняются после увеличения версии. Next/Vercel остаётся прежним адаптером. Supabase Auth как новая личность администратора не вводится.

Тяжёлое вычисление PBKDF2 вынесено из Cloudflare Worker Free в отдельную Supabase Edge Function `admin-password-crypto`. Функция знает только операцию проверки/создания хеша и не имеет доступа к БД, сессиям или service-role ключу. Она требует отдельный серверный секрет `AYPROM_ADMIN_CRYPTO_KEY`; Worker передаёт тот же секрет через `ADMIN_CRYPTO_KEY` и использует публичный Supabase ключ для вызова функции. Чтение credential row, ограничение попыток, выдача cookie и CAS-запись новой версии остаются в Worker. Функция не вызывается из браузера.

Добавлены защищённая страница `/admin/security` и POST `/api/admin/password`: действующая сессия и same-origin обязательны, текущий пароль проверяется, новый пароль получает тот же формат хеша, CAS-запись увеличивает версию, cookie очищается. При ошибках вход/смена пароля закрываются без fallback на более слабую проверку. Прямой доступ к `/admin/security.html` запрещён.

## Доказано локально

- TDD: тесты функции, ограниченного HTTP-клиента, портов и смены пароля сначала обнаружили отсутствие поведения, затем прошли.
- `npm run check`: lint, typecheck, colors и Vitest завершились с кодом 0; 179 test files passed, 1 skipped, 1584 tests passed, 4 skipped. jsdom сообщил лишь о неподдерживаемой навигации в одном старом UI-тесте.
- Свежий `AYPROM_STATIC_BUILD=1 npm run build` на уже запущенной локальной Supabase: 36/36 статических страниц, код 0. Crawl из этого build: 90/90 маршрутов записаны без ошибок, 12 alias помечены ожидающими проверки redirects. Диагностический browser origin не предназначен для выпуска.
- Настоящий локальный Supabase Edge Runtime выполнил существующий и новый PBKDF2 hash; настоящий workerd принял верный пароль, отклонил неверный и отозвал старую сессию после смены версии. Собственный изолированный стек остановлен после проверки.
- Пакет из свежего публичного staging собран локально: 183 asset-файла, Worker 72 843 bytes / gzip 16 655 bytes; SHA-256 inventory сошёлся. `ready: false`, `previewReady: true`, `productionReady: false`.
- Повторный smoke именно свежего упакованного Worker с изолированной Supabase и браузером без JavaScript: 21/21 проверок, включая публичные страницы/поиск, защищённую админку, отказ гостю, вход, смену пароля и отзыв старых сессий; `cleanup: true`.

## Не доказано и следующая граница

- Нет remote staging на Cloudflare/Supabase: реальные лимиты CPU, квот и маршрутизация Static Assets ещё не измерены. Локальный workerd не применяет Cloudflare Free CPU limit. Supabase Edge Function также не проверена на удалённом бесплатном тарифе.
- Сборка функции в удалённом Supabase и настройка двух одинаковых секретов требуют отдельного безопасного staging/release. Никаких production secrets сейчас не создавали и не меняли.
- Пакет использует диагностическую публичную сборку: browser Supabase origin в ней намеренно непригоден для выпуска. Нужны release-compatible build, полный admin CRUD/media и удалённые E2E перед переключением DNS.
- Рабочий Vercel, production Supabase/R2, DNS и Cloudflare account не менялись. Push/deploy не выполнялись. Миграция не завершена.
