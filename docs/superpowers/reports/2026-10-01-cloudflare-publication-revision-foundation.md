# Локальная основа для публикации правок каталога

Состояние: отдельная ветка `codex/cloudflare-integration`; ни работающий Vercel-сайт, ни production Supabase/R2/Cloudflare не менялись. Новая миграция не применялась к общей локальной базе или production.

## Зачем

Статические страницы Cloudflare — сохранённые HTML-файлы. Изменение наличия или карточки в базе само по себе их не обновляет. До подключения admin mutations нужен номер версии каталога, позволяющий будущей сборке обнаружить, что данные изменились во время её работы, и отказаться публиковать устаревший результат.

## Изменение

- `supabase/schemas/prod.sql`: singleton `content_revision`, публичная функция `get_content_revision()` только для чтения и statement-триггеры на 11 публичных таблицах. Каждая транзакция может увеличить номер несколько раз из-за существующих вложенных триггеров; гарантия — монотонность для подтверждённых изменений и откат вместе с транзакцией, а не «ровно +1 за нажатие кнопки».
- `supabase/migrations/20261001064152_content_publication_revision.sql`: сгенерирована штатным для этого проекта `supabase db diff -f content_publication_revision`, затем вручную сужены права клиентских ролей (`REVOKE ALL` до `GRANT SELECT`) как защита от старых default privileges. SQL полностью просмотрен: нет удаления/изменения прежних объектов.
- `supabase/tests/database/publication_revision.test.sql`: 13 pgTAP-утверждений о правах, изменении, откате и покрытии таблиц.
- `scripts/cloudflare/local-publication-revision-smoke.mjs`: отдельный Supabase-проект на портах 564xx, pgTAP, публичный RPC через настоящий PostgREST, остановка и удаление только собственного временного проекта.

## Не доказано и следующий шаг

Счётчик пока не связан с реальной сборкой/публикацией: нет чтения версии **до** сборки и **после** crawl, нет очереди повторной сборки, атомарного переключения сайта, показателя статуса публикации в админке, CRUD/media parity и remote-проверки Cloudflare Free. Поэтому нельзя включать кнопки изменения каталога в Cloudflare-админке или называть её полной. Следующий безопасный участок — revision fence сборщика с отказом при изменившейся версии, затем локальный end-to-end сценарий «правка → новая сборка → проверка → переключение/откат» в отдельном тестовом стенде.

## Продолжение: публичное чтение версии и локальный fence

После первого checkpoint добавлен Node-side `src/cloudflare/static-build/producer/publication-revision.ts`. Он допускает только publishable/anon ключ, принимает HTTPS или loopback HTTP, делает один POST к публичному RPC без service-role, не следует redirect, ограничивает ответ 64 байтами и 10 секундами и возвращает только безопасное целое. Ошибки не содержат URL, ключа или тела ответа. `runRevisionFencedWork` читает номер до и после callback подготовки staging; при изменении не возвращает его как успешный результат. Callback не имеет права переключать рабочий сайт — проверка перед будущим promotion всё равно понадобится.
