# Проверка полноты снимка каталога

Только локальная подготовка Cloudflare-сборки. Публикации и запросов к production Supabase не было.

Раньше `loadLocalCatalogSnapshot` прекращал чтение таблицы, если ответ содержал меньше 1000 строк. При серверном лимите ниже 1000 это могло тихо исключить товары из статического сайта. Теперь каждый GET просит `Prefer: count=exact`, сверяет диапазон и общее число из `Content-Range`, продолжает чтение до полного числа и отказывает при отсутствии/искажении счёта или его изменении между страницами. Запросы используют только публичный ключ; service-role не добавлялся.

TDD: до исправления 3 из 5 целевых тестов падали; фикстура с лимитом 2 строки загружала 2 товара из 5. После исправления целевой набор прошёл, включая новый тест смены общего числа между страницами. Полный `npm run check` дошёл до Vitest после успешных lint/typecheck/check:colors; отдельный полный `npm test -- --reporter=dot` завершился с кодом 0: 1786 passed, 4 skipped.

Первый запуск `node scripts/cloudflare/local-publication-revision-smoke.mjs` остановился до проверок: Docker API был недоступен. После включения Docker повторный запуск завершился с кодом 0: 14/14 этапов, включая настоящие PostgREST и публичный RPC, Next build и полный crawl, пакет Worker, Chromium и отказ устаревшему пакету; `cleanup: true`.

Затем `node scripts/cloudflare/local-snapshot-cap-smoke.mjs` поднял отдельный временный Supabase с `max_rows=2`. Прямой публичный GET запросил 1000 строк, но настоящий PostgREST вернул ровно две и `Content-Range: 0-1/5`. Тот же публичный ключ через `loadLocalCatalogSnapshot` получил все пять товаров за запросы с `offset` 0, 2, 4. Код выхода 0, `cleanup: true`: изолированные контейнеры и временные папки удалены, общий Supabase не останавливался. Удалённого Cloudflare и production-публикации не было.
