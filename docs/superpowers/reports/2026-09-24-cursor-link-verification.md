# Cursor: проверка внутренних ссылок в staging

- Дата: 2026-09-24
- Ветка: `codex/cursor-canonical`, исходный HEAD `0754369593316edf1b4b623a4621e9d5b2c7099c`
- Статус: локальный этап. Без push, merge, deploy.

После скачивания страниц и копирования файлов producer читает ссылки `<a href>` обычным HTML-парсером parse5. Строгий XML-парсер к страницам не применяется. Сетевых запросов нет.

Ссылка на наш сайт считается:
- найденной, если это страница из манифеста или уже скопированный файл;
- ожидающей, если это адрес `/product/...` (перенаправление ещё не проверяется вживую);
- исключением runtime для `/admin` и `/api`, без заявления, что это статическая страница.

Относительный адрес считается от URL страницы. Полный адрес нашего сайта сначала разбирается, и только потом сравнивается origin: существующая страница принимается, отсутствующая даёт broken. Query и fragment на такой ссылке не делают страницу чужой. Protocol-relative (`//чужой-сайт`) и внешний `https` не загружаются. `mailto` и `tel` тоже не загружаются. Другой внутренний адрес даёт отказ `link_verification_failed`.

Битая percent-кодировка пути или fragment (`%ZZ`) не обрывает producer. Она становится записью `invalid_link` без исходного текста ссылки.

Отчёт: `meta/link-verification.json`. В нём только путь и статус, без query, секретов и исходного HTML. `dist/site` не меняется.

Штатный fixture содержит ссылки на `/catalog`, `/catalog?q=1` и `#page`, поэтому успешный запуск реально их проверяет.

Не входит в этап: настоящий `next build`/`next start`, перенос staging в `dist/site`.
