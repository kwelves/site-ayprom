# Механизм согласованного выпуска: локально проверенная точка, 2026-10-08

Реализован внешний Node coordinator — программа, которая управляет порядком
выпуска и восстановления. Она соединяет проверенный пакет, неактивную версию,
журнал, приватные операции каталога и очередь. Публичный Worker, Next/Vercel,
маршруты сайта и запись админки в этом блоке не менялись.

В обычном пути сначала проверяются прежний сайт, снимок и подтверждение очереди.
После проверки неактивной версии снимок становится ready. Затем переключаются
версия сайта и указатель каталога, проверяется выдача, подтверждается очередь и
записывается published. Перед каждым переключением сохраняется намерение.
Ошибки компенсируются только после проверки фактических id и состояния базы.
Старые снимки, пакеты и медиа не удаляются механизмом восстановления.

прерванная, но ещё не подтверждённая попытка восстанавливает прежнее состояние.
Неизвестное подтверждение сначала сверяется с фактической записью очереди:
уже совершённый confirm не повторяется и не откатывается вслепую.

## Общая проверка и границы

`npm run check`: exit 0; 223 files passed / 1 skipped,
2082 tests passed / 4 skipped; lint, TypeScript и цветовые контракты прошли.
В этом запуске было 10 предупреждений о неиспользованных параметрах новых
тестов. После добавления проверок этих параметров целевой eslint завершился
без предупреждений; та же группа 60 passed и TypeScript exit 0.
Исполняемый код после полного gate не менялся. Сообщения jsdom о навигации
остались; пропущенные тесты не считаются пройденными.

Graphify: exit 0, 5302 nodes / 10449 edges / 420 communities.
git diff --check: exit 0. Поиск импортов подтвердил, что coordinator подключён
только внешними Node-файлами и тестами. Новые правила SQL/доступа не добавлялись.

На стороне базы CAS атомарный. Проверки Cloudflare обнаруживают наблюдаемые
чужие изменения, но сами по себе не доказывают серверную условную активацию.
Перед настоящим выпуском нужны проверенный provider transport, корреляция
ответов с фактическим переключением и единый канонический журнал для всех
управляющих процессов данного Worker. Параллельные ручные действия провайдера
не защищены транзакцией базы. Оставшаяся после аварийного завершения блокировка
журнала не удаляется автоматически и требует отдельной проверки владельца.
Тест восстановления здесь моделирует прерывание с освобождённой блокировкой,
а не внезапное завершение процесса/питания.

Никаких push/deploy, удалённого SQL, production-изменений, перезапусков общих
служб, изменений основной папки или чужих worktrees. Новые локальные артефакты
сохранены, секреты в журнал/пакет/отчёт не записывались.
