# Node-обработчик товарных фотографий

Исходный HEAD: `ccbe260`, ветка `codex/cloudflare-integration`. Только локальные изменения. Никаких upload/deploy, БД, запуска общих сервисов или правок production.

## Что реализовано

`src/cloudflare/media/product-photo-processor.mjs` принимает уже подготовленные браузером байты, режим и серверные идентификаторы товара/фото. Повторно использует `validateRasterImage`, текущие `enhanceProductPhotoBuffer` / `convertBufferToWebp` и `generateProductImageVariants`. Копии алгоритмов улучшения/сжатия нет. В результате — полный набор master, thumbnail и gallery с прежними путями, MIME, размером и полным SHA-256. Никакой записи или сетевого запроса внутри нет; вызывающая сторона получает весь набор только после успешного завершения.

- `normal`: полученные байты сохраняются как master.
- `webp`: браузер уже преобразовал файл; дополнительного сжатия нет (прежнее поведение).
- `script`: прежний pipeline с квадратным PNG, коррекцией и водяным знаком.
- `script-webp`: тот же pipeline, затем прежний WebP q82.

Проверяются тип, сигнатура, размер 8 MiB, прежние ограничения разрешения, безопасные сегменты пути и режим. Многокадровый файл отклоняется до улучшения, чтобы не потерять анимацию молча. Входные байты и метаданные копируются до первого await. Исключения наружу содержат только фиксированные `photo_processing_failed` и `rule`, без имени файла, содержимого или текста декодера.

Legacy Next actions и Worker не изменены. Этот модуль предназначен для отдельного Node runner, а не для request runtime Worker. Его нельзя импортировать в `worker.ts`.

## Что это не доказывает

Сравнение выполнено на одной ОС и установленной версии Sharp, не с историческими файлами до обновления Sharp и не в Linux Workers Builds. Межплатформенное совпадение водяного знака/шрифтов и реальные пользовательские 4K-фото ещё нужны. SEC-04 не закрыт.

Нет authenticated API загрузки, приватного R2, очереди, lease/повторов/отмены, атомарной записи `product_images` и публикации ревизии. Процессор не запускается автоматически из админки. SHA-256 — идентификатор содержимого, не подпись и не разрешение записывать в БД.

Время всей обработки и память должны ограничиваться родительским процессом runner; текущие Sharp-проходы вариантов имеют прежний timeout, но raw-проходы улучшения не отменяются через Promise. Следующий участок: job-state и изолированное выполнение с принудительным завершением, затем подключение приватного хранилища и финализации. Ошибка обработки не должна делать частично готовое фото публичным или менять действующий каталог.
