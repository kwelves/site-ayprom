# Private staging / public media R2 adapter (2026-10-03)

Status: **partial, local only**. No account access, test-bucket write, production R2 write, Worker route change or deploy.

`src/cloudflare/media/photo-r2-storage.mjs` supplies the three storage operations needed by the Node-only photo-job runner. It uses the project's already pinned AWS S3 client, but receives its configured client and two distinct bucket names from its caller; credentials are never read or logged here. The staging source can be read only from the private bucket, while final objects can be conditionally created (`If-None-Match: *`) and checked by HEAD only in the separate public-media bucket. Reusing the same bucket is rejected before any request. Source reads are limited to 8 MiB by both declared length and actual streamed bytes; requests have a 20-second abort signal. Keys, upload size, MIME type and SHA-256 are validated before writes. Errors expose only fixed codes, not bucket names, paths, credentials or server text. The Node runner separately compares returned HEAD metadata with the actual processed bytes before database finalization.

[Cloudflare's S3 compatibility guide](https://developers.cloudflare.com/r2/api/s3/api/) lists conditional `PutObject` support; its [consistency guide](https://developers.cloudflare.com/r2/reference/consistency/) describes immediate visibility of writes. These docs support the proposed protocol, but the local HTTP server is **not** Cloudflare R2. The required external gate is an isolated test R2 bucket: actual conditional-write behavior, HEAD metadata, private/public separation, CORS/presigned browser upload, and cleanup/reconciliation. Until that gate and the pending final database-migration test pass, the photo flow is not connected to admin UI or production.
