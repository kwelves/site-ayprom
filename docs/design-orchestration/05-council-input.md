# LLM Council Input — редизайн AYPROM

## Контекст AYPROM

AYPROM — B2B-сайт-каталог гидравлического оборудования и запчастей для спецтехники (не SaaS, не стартап-лендинг, не арт-сайт, не обычный e-commerce с ценами/корзиной). Аудитория: владельцы спецтехники, механики, инженеры, снабженцы, руководители автопарков, сервисные компании — им нужна быстрая ориентация в каталоге из ~5 000–9 000 позиций, а не развлекательный визуал. Целевая атмосфера — современная промышленность, инженерная точность, тяжёлая техника, профессиональная гидравлика: премиальный, но сдержанный B2B-визуал, уверенность, технологичность. Допустимые референсы — CAD/blueprint/техдокументация/инженерные схемы/чертёжные линии, точная механика, промышленная фотография, металл/гидравлика/спецтехника, глубокий фирменный синий; недопустимы неоновый cyberpunk, игровой интерфейс, избыточное стекло/glow, luxury-fashion эстетика, типовые SaaS-шаблоны, фиолетовые AI-градиенты, декор без бизнес-функции.

## Non-negotiables (зафиксировано Lead Orchestrator, не подлежит пересмотру Council)

- AYPROM остаётся сайтом-каталогом (не превращается в лендинг/арт-сайт).
- Существующие товары и категории сохраняются.
- Существующие рабочие URL не ломаются (включая `/catalog/category/[slug]/...`, `/catalog/brand/[slug]/...`, `/catalog/vehicle-type/[slug]`, канонический редиректор `/product/[slug]`).
- Контактные сценарии сохраняются (поиск через `/catalog?q=`, кнопки перехода к каталогу/маркам).
- Реальные данные не заменяются mock-данными — источник истины: Supabase через `src/lib/queries/*`, тип `Product`/`ProductListItem` (`src/types/catalog.ts`).
- Фирменная идентичность сохраняется: `--color-primary: #084bb9` (blue-600), `--color-accent: #084bb9` on blue-50, `--color-ring: #4f91f8`. Новые токены — только производные (glow/rgb) от этих значений.
- Логотип не переделывается без прямого требования.
- Не использовать чужие изображения через hotlink (в т.ч. с gidravlikov.ru).
- Не копировать сайты-конкуренты дизайном/кодом/разметкой.
- Mobile — отдельная продуманная композиция, не пропорциональное сжатие desktop.
- Сайт остаётся быстрым — одно фоновое видео на Hero-сцену, без Three.js/WebGL/тяжёлых 3D-библиотек.
- Визуальные эффекты не мешают выбору товара (каталог, поиск, карточка товара — приоритет над декором).
- Доступность и читаемость обязательны (контраст, keyboard nav, focus-visible, aria-label, prefers-reduced-motion).
- SEO-важный контент не должен исчезать из HTML (server-rendered контент остаётся server-rendered).
- Не должно быть hydration errors.
- Сборка Vercel должна проходить на каждом чекпоинте.
- Не проводить полный rewrite без технической необходимости — переиспользовать `ProductCard`, `Button`, query-функции, существующую per-vehicle геометрию `VehicleShowcaseCard`, где это возможно.
- Не менять архитектуру (App Router, Supabase, npm) ради удобства дизайнера.
- Не превращать весь сайт в один тяжёлый анимационный экран.
- Зарезервировать fixed bottom-right угол (z-50+) под будущий WhatsApp-бейдж — пока не реализован в коде, но зафиксирован в `CLAUDE.md`/`PROJECT_BRIEF.md` как обязательный.
- Библиотека анимаций — уже установленный `framer-motion ^12.42.2`, не новый пакет `motion`.
- Package manager — npm (`package-lock.json`), не менять.

## Топ-8 рисков (из risk register)

1. Объединение Hero-видео и VehicleShowcase-видео в одну client-side сцену повторяет паттерн, который уже один раз сломал сборку (задокументированный прецедент отката).
2. Возможное прямое противоречие: "объединить в интерактивную сцену" vs non-negotiable "одно фоновое видео на Hero-сцену / не превращать сайт в один анимационный экран" — нужно явное решение пользователя, что значит "объединить".
3. Scroll-driven/pinned-сцена рискует scroll-jacking, что для B2B-аудитории, которой нужно быстро попасть в поиск/каталог, — прямой конверсионный минус.
4. Редизайн формы поиска в Hero может незаметно сломать GET `/catalog?q=` — единственный основной инструмент навигации по 5–9 тыс. товаров.
5. Рефакторинг VehicleShowcaseSection рискует случайно задеть вручную откалиброванную per-vehicle геометрию (placement/shadows), не заметив регрессии до QA на реальных фото.
6. "Невидимость" VehicleShowcaseSection может быть багом scroll-reveal, а не только визуальной проблемой — визуальный редизайн без диагностики рискует замаскировать причину.
7. Требование "mobile — отдельная композиция, не сжатие desktop" резко увеличивает объём работы; есть риск, что агенты по умолчанию спроектируют responsive-сжатие одной desktop-идеи.
8. Индустриально-декоративные элементы (чертёжные линии, glow, overlay), уместные на Hero, могут "утечь" в каталог/карточку товара, где декор прямо запрещён иметь приоритет над выбором товара.

## Четыре концепции

### 1. Precision Wayfinding («Точная навигация») — ui-ux-pro-max

**Главная идея.** Сквозной «контекстный слой» — breadcrumbs + активные фильтры-чипы + счётчик результатов — одинаковый от Hero до карточки товара, вместо трёх несвязанных точек входа (Hero-поиск, форма `/catalog`, дропдауны Header). Диагноз: у B2B-аудитории (механик, снабженец) единственная валюта конверсии — «быстро нашёл нужную позицию»; текущая структура функциональна, но не связана общей системой ориентиров — это IA-разрыв, а не косметика.

**Что сохраняется.** Все URL/роуты, backend-поиск и пагинация, `ProductCard`/`Button`/`SectionHeading`/`BackButton`, per-vehicle геометрия `VehicleShowcaseCard`, одно фоновое видео Hero, sticky Header, резерв под WhatsApp, цветовые токены.

**Hero.** Структура не меняется. Под CTA и формой поиска — ряд из 4–6 quick-access чипов (топ-категории/типы техники → `/catalog/category|vehicle-type/[slug]`). Это не филлер под пустотой, а второй вход для тех, кто ещё не знает точный запрос.

**Спецтехника (VehicleShowcase).** Геометрия и фон-видео не трогаются. Диагноз «невидимости»: карточки читаются как декоративный коллаж — нет постоянно видимого (не hover-only) лейбла-CTA. Решение — видимый кликабельный чип-подпись на каждой карточке («Экскаваторы · 340») → `/catalog/vehicle-type/[slug]`. Если после этого секция всё равно не считывается — это подтвердит гипотезу бага scroll-reveal/stagger, требующую отдельной проверки анимационного агента.

**Каталог.** Единая context-bar на всех уровнях: breadcrumbs (обязательны от 3+ уровней) + «Найдено: N». Facet-панель — три группы по существующей доменной модели (Категория/Подкатегория, Бренд, Тип техники) как ссылки-чипы через query-параметры к тому же backend RPC, без клиентского состояния каталога и без загрузки каталога на фронт. Desktop: sticky filter-rail 260px + грид. Mobile: bottom-sheet вместо сайдбара, фильтры-чипы под кнопкой с горизонтальным скроллом. Сортировка — только релевантность/название, без цены. Пустой результат — не «0», а сообщение + ссылки на соседние категории.

**Карточка товара.** `ProductCard` не переписывается. Добавляется breadcrumb и блок «Похожие товары» под описанием (тот же подкатегория/бренд-запрос с лимитом), чтобы карточка не была тупиком. Основной CTA — звонок/WhatsApp, не «в корзину».

**Header/поиск.** Компактная иконка-поиска в Header видна на всех страницах, открывает inline-input с тем же action `/catalog?q=`, что и Hero-форма — одна реализация (`ProductSearchForm`), не два расходящихся поведения. Дропдауны получают явное активное состояние (`aria-current`).

**Новые компоненты.** `Breadcrumbs`, `ActiveFilterChips`, `CatalogContextBar`, `FilterRail`/`FilterSheet`, `HeaderSearchTrigger` — тонкие обёртки, без нового каталога на клиенте.

**Motion.** Только существующие обёртки framer-motion (`Reveal`, `Stagger`, `springSmooth`) — новых паттернов не вводится. FilterSheet на mobile переиспользует уже применённую в мобильном меню height-анимацию. Смена активных чипов — fade/scale 150–200ms без layout-shift. `prefers-reduced-motion` уважается везде.

**Цвет.** Токены не меняются. Facet-панель и активные чипы используют существующий `--color-accent` для активного состояния. Breadcrumbs — нейтральный `muted-foreground`, текущий уровень — `foreground`.

**Accessibility/производительность.** Контраст 4.5:1, `aria-expanded/controls` на FilterSheet и дропдаунах, `aria-live="polite"` для «Найдено: N», focus-visible через `--color-ring`. Facet-панель и breadcrumbs — server components где возможно; клиентское — только раскрытие FilterSheet на mobile и опциональный debounce автоподсказок.

**Риски.** (1) Facet-панель рискует скатиться в e-commerce-чекбоксы — держать как ссылки-чипы. (2) Дублирование поиска Hero/Header должно опираться на один компонент, иначе поведение разъедется. (3) Breadcrumbs на mobile при глубоких путях не влезут в строку — сворачивать до «Назад к [уровень]». (4) Facet-counts могут потребовать нового агрегирующего RPC — не блокировать релиз базовой навигации ради этого.

**Fallback.** Минимум: только `Breadcrumbs` на страницах категории/бренда/товара + компактный поиск в Header + видимые подписи на VehicleShowcase — устраняет три главных IA-разрыва почти без риска для сборки.

**Техническая сложность.** Средняя. **Уверенность:** 8/10.

### 2. Blueprint Precision («Чертёжная точность») — high-end-visual-design

**Главная идея.** AYPROM визуально ведёт себя как техпаспорт спецтехники: глубокий фирменный синий работает как цвет инженерного чертежа, а тонкие выносные линии, координатные метки и подписи-аннотации организуют пространство вместо пустых белых промежутков. Премиальность через инженерную дисциплину, а не люкс-глянец — точнее ложится на аудиторию, чем SaaS-паттерны (glass, neon).

**Что сохраняется.** Токены `--color-blue-*`/`--color-primary`/`--color-ring`, Geist (sans+mono, без новых шрифтов), только framer-motion, откалиброванная geometry `VehicleShowcaseCard`, `ProductCard`/`Button`/query-слой/все URL, форма поиска `GET /catalog?q=` без изменений логики, одно фоновое видео на Hero, резерв под WhatsApp.

**Hero.** Видео сохраняется (pause вне вьюпорта, poster, prefers-reduced-motion). Добавляется тонкий HUD-слой: угловые «crop-mark» скобки (SVG 1px, blue-600 @30–40%, aria-hidden), вертикальная координатная линейка сбоку, увеличенная типошкала с уменьшенным tracking. Поисковая форма переосмыслена как «панель ввода» (тонкая обводка, Geist Mono плейсхолдер) без изменения action/name.

**Спецтехника — ключевое решение.** НЕ объединять Hero-видео и VehicleShowcase в единую pinned/scroll-jacking сцену (учтён зафиксированный риск прошлого отката). Вместо этого VehicleShowcaseSection становится статичным «аннотированным индексом техники»: сетка фото (2×4 desktop / 1 колонка mobile) на светлом чертёжном фоне (микро-сетка blue-600 @4–6%), выносные линии к подписям, клик → `/catalog/vehicle-type/[slug]`. Существующая per-vehicle geometry переиспользуется. Второе ambient-видео (`vehicle-showcase-background.mp4`) рекомендуется убрать — это чинит «невидимость» контента и снижает видео-нагрузку страницы.

**Каталог и карточка.** Категорийные плитки — фото-карточки с hairline-обводкой blue-600/10 и одним срезанным углом (clip-path 12–16px) вместо border-radius. `ProductCard` структурно не меняется; добавляется угловая скобка на hover/focus и моноширинный артикул. Фильтр-чипы — прямоугольные со срезанным углом, не пилюли.

**Типографика и цвет.** Явная шкала на базе Geist: Display 56–96px, H2 32–40px, body 16–18px, eyebrow 11–12px uppercase. Geist Mono точечно — для артикулов/координат/номеров секций. Базовые цветовые токены не трогаются; добавляются только производные: `--grid-line` (blue-600@4–6%), `--hairline` (blue-600@10%), тёплый off-white для фото-подложек, графитовый серый.

**Motion.** Только framer-motion, переиспользуются существующие варианты (fadeUp/fadeIn/staggerContainer/springSmooth). Новое: «line-draw» reveal для SVG-линий (stroke-dashoffset), hover-скобки (opacity/scale, GPU-safe). prefers-reduced-motion отключает line-draw/parallax без слома layout.

**Прочее.** Header — тонкая sticky-панель, мега-меню как «легенда чертежа». Footer — «спецификационная панель» вместо строки копирайта. Между секциями — линия-разделитель с координатной меткой («02/05») вместо пустоты. Фотостиль — реальная предметная съёмка техники/узлов, единая студийная схема света, без lifestyle/стоков. Accessibility: все декоративные SVG aria-hidden, контраст новых подложек проверяется на WCAG AA.

**Performance.** Чистая экономия: удаление второго видео снижает декодируемый видеообъём страницы до одного (Hero). Line-draw — только transform/opacity/SVG stroke.

**Сложность.** Средняя: новый typography-слой + лёгкие SVG/CSS-компоненты + реструктуризация VehicleShowcaseSection без ambient-видео.

**Риски.** (1) Нехватка качественных реальных фотоактивов техники в едином свете — без них эффект частично деградирует к текущим фото каталога. (2) Риск «сползания» чертёжных элементов в гиммик при неаккуратной реализации. (3) Срезанные углы на карточках нужно протестировать на плотных сетках (2000+ товаров), чтобы не читались как шум. (4) Удаление ambient-видео VehicleShowcase — поведенческое изменение существующей секции, требует согласования, не тихой замены.

**Fallback.** Сохранить текущую структуру секций, ввести только типошкалу + Geist Mono для чисел, выровнять ритм отступов между секциями, заменить блок «О компании» на текст + одну реальную фотографию с подписью — без декоративного SVG-слоя.

**Уверенность: 7/10.** Реальный эффект премиальности сильно зависит от качества фотоактивов (пока не подтверждены) и от дисциплины реализации декоративного слоя.

### 3. Drawing Sheet System («Чертёжный лист») — design-taste-frontend

**Дилы:** DESIGN_VARIANCE 7/10 · MOTION_INTENSITY 5/10 · VISUAL_DENSITY 5/10. Baseline читается как ~3/4/3 (центрированный hero, повторяющийся грид, пустой воздух без контента) — variance и density подняты умеренно за счёт реального контента и асимметрии, а не декора; motion оставлен средним, поскольку аудитория должна быстро попадать в поиск.

**Главная идея.** Тонкая координатная сетка, угловые регистрационные метки и SVG leader-line выноски связывают Hero, VehicleShowcase и «О компании» в единый инженерный документ. Пустые межсекционные разрывы устраняются функциональной связностью (линии, чипы, ссылки), а не декором или удлинением текста.

**Hero.** Остаётся одно фоновое видео (без изменений в логике autoplay/muted/loop/IntersectionObserver-паузе/prefers-reduced-motion). Композиция меняется с центрированной на асимметричный сплит: заголовок и поиск — в левые 7 колонок, видео — бордер-ту-бордер справа. По углам видео-зоны — 4 L-образные corner registration marks (blue-100/40%, decorative, aria-hidden) — единственный чисто декоративный элемент. В правом нижнем углу видео — компактный callout с реальными цифрами (категории/товары из БД, не выдуманные).

**Спецтехника (VehicleShowcase).** Ручная per-vehicle геометрия карточек не трогается. Hero-видео и showcase-видео сознательно НЕ объединяются в одну сцену — прямой отказ от паттерна, который уже один раз сломал сборку и противоречит non-negotiable «одно фоновое видео на Hero». Вместо слияния — синхронизация hover/focus-состояний: карточка техники подсвечивает leader-line к заголовку секции и соответствующий чип в новой полосе «Совместимость по типам техники» (client-leaf, локальный useState, без глобального стейта). Второй imagery-блок (кран/стройка) перерабатывается именно в эту content-полосу с реальными ссылками на `/catalog/vehicle-type/[slug]` вместо фонового видео без текста.

**Каталог и карточка товара.** Вне фокуса цикла. Только заголовок страницы категории получает тот же hairline-язык (тонкая рамка вокруг фильтр-панели). Сетка товаров, приоритет выбора товара, карточка товара — не меняются буквально, никакого декора внутри.

**Motion.** Только framer-motion: `whileInView` reveal через существующие Reveal/Stagger, leader-lines как SVG `pathLength` 0→1 (~500ms, easing [0.16,1,0.3,1], `viewport once:true`), hover-sync через CSS transition/whileHover. Явно запрещены GSAP, scroll-hijack и pin-стек. `prefers-reduced-motion` схлопывает leader-lines и corner-marks в статичные линии.

**Цвет.** Без новых accent-цветов — только производные blue-600/blue-50. Hairlines: blue-100 на белом (~40-60% opacity), white/15% поверх видео. Один accent на всю страницу.

**Что не трогается.** Header (sticky/overPhoto), форма поиска `/catalog?q=`, токены `--color-primary/accent/ring`, Button (cva), ProductCard, все URL/слаги, framer-motion как единственная motion-библиотека.

**Новые компоненты.** `DraftingFrame`/`GridOverlay` (server-safe CSS/SVG wrapper, pointer-events-none), `LeaderLine` (client-leaf, framer-motion SVG), `VehicleCompatibilityStrip` (server + client hover-sync leaf).

**Accessibility/Performance.** Hairlines/marks/leader-lines — aria-hidden, pointer-events-none; реальная навигация (чипы, ссылки) полностью доступна с focus-visible:ring, WCAG AA сохраняется. Никаких новых тяжёлых ассетов — leader-lines - лёгкий inline SVG, GridOverlay - чистый CSS, LCP-путь Hero-видео не меняется.

**Главные риски.** (1) SVG leader-line может рассинхронизироваться с геометрией карточек на промежуточных вьюпортах — нужен протестированный mobile/tablet fallback (простые hairline-разделители). (2) Риск отката к идее объединения hero- и showcase-видео под предлогом «интерактивности» — явно отклонено в этой концепции. (3) Compatibility-полоса требует реальных агрегатных чисел по типам техники; если запрос не готов к сроку — чипы без чисел, без выдуманной точности.

**Fallback.** Если SVG leader-lines рискованны технически: оставить только hairline section-dividers (1px blue-100) и заполненную content-полосу без анимации отрисовки, corner marks убрать полностью.

**Оценка уверенности: 7/10.**

### 4. Schematic Spine («Технический лист») — anthropic-frontend-design

**Главная идея.** Заполнить пустые межсекционные промежутки (Hero → VehicleShowcase → About → Footer) не декором, а грамматикой инженерного чертежа — тонкий вертикальный «шов» (spine) с выносными линиями (leader-label), несущими реальные данные каталога (масштаб, число брендов, число позиций), плюс угловые CAD-скобки вокруг Hero-видео. Footer перерабатывается в «title block» (реальная навигация) вместо строки копирайта. Это единственная референсная территория, принадлежащая именно гидравлике/спецтехнике, а не generic B2B — отличает AYPROM от hyva.com.ua.

**Типографика.** Вторая роль для уже используемой Geist — **Geist Mono** через `next/font/google` (без новой внешней зависимости) для всех «данных»: артикулы, характеристики, счётчики позиций, лейблы шва. Проза/заголовки остаются на Geist Sans.

**Цвет.** Без новых токенов. Линии шва/скобки — производные rgba от уже зафиксированных `--color-primary` (#084bb9) и `--color-ring` (#4f91f8). Тёмные секции — существующая Tailwind slate-900/950. Никакого нового акцентного цвета — сознательно отклонено ради дисциплины «только синий + белый + графит».

**Hero.** Без структурных изменений видео/формы/CTA. Добавляются только 4 тонких угловых CAD-скобки по периметру видео (~24×24px, blue-500/40, `pointer-events-none`) и опциональная строка-«спецификатор» (Geist Mono, кросс-фейд 2-3 факта каталога) — первый кандидат на вырезание, если будет ощущаться избыточным.

**Спецтехника (VehicleShowcase).** Геометрия `placement`/`shadows` полностью не трогается. «Объединение» с Hero — через продолжение шва/выносных линий из подвала Hero в шапку секции, а не через слияние видео-слоёв (сознательно избегает прецедента, сломавшего сборку ранее). При hover на карточке — короткая CSS leader-line к лейблу с числом совместимых категорий (реальные query-данные).

**Каталог и карточка товара.** Шов присутствует только как тихий фоновый ватермарк за карточками (`-z-10`, никогда не пересекает поиск/CTA). Счётчики позиций и артикулы/характеристики в карточке товара — Geist Mono, усиливает уже существующий «datasheet»-характер карточки. Backend-поиск, пагинация, структура компонентов — без изменений.

**Mobile.** Вертикальный шов заменяется горизонтальной «линейкой»-риской под sticky-хедером на главной, с компактными горизонтальными разделителями между секциями («— 5 000+ позиций —»). Отдельная композиция, не сжатие desktop-версии; карточки техники остаются в 2 колонки.

**Motion.** Только framer-motion, уже используемые обёртки `Reveal`/`Stagger`. Draw-in линий шва при скролле (`scaleX`/`opacity`), hover leader-line на карточках техники (CSS `group-hover`), кросс-фейд спек-тикера в Hero. Явно исключены: pinned/scroll-jacking, объединение видео в один клиентский слой, параллакс на крупных блоках. `prefers-reduced-motion` отключает все draw-in анимации.

**Новые компоненты.** `SchematicSpine`, `LeaderLabel`, `CornerBracket` — все серверные, чисто декоративные (div/border/inline-SVG), `aria-hidden`. Изменяется существующий `Footer` (title-block редизайн). Ноль новых client-границ, ноль новых видео/изображений.

**Accessibility/Performance.** Декор — `aria-hidden` + `pointer-events-none`; текстовые data-лейблы — обычные читаемые элементы с AA-контрастом. Geist Mono — один доп. self-hosted файл через `next/font`, без CLS. Бандл не растёт за счёт CSS-only взаимодействий.

**Главные риски.** (1) Калибровка тонких линий шва требует визуальной итерации со скриншотами, которая не проводилась (без разрешения на превью) — риск «пририсованного» вида. (2) Числа в leader-label должны быть реальными подсчётами из Supabase, не выдуманными. (3) Footer как общий layout-компонент нужно менять аккуратно, не сломав существующие ссылки. (4) Контраст шва поверх видео VehicleShowcaseBackground нужно проверить отдельно на светлых/тёмных кадрах.

**Fallback.** При избыточности шва: оставить только переработанный Footer-title-block + Geist Mono для артикулов/характеристик/счётчиков — устраняет «пустой футер», даёт узнаваемую деталь почти без риска.

**Сложность.** Средняя — Tailwind-утилиты + 2-3 серверных презентационных компонента + правка Footer + вторая гарнитура. Ноль изменений в data-layer, роутинге, RLS, геометрии VehicleShowcase.

**Уверенность:** 7/10 — концепция технически реализуема без новых зависимостей и без риска для non-negotiables, но качество исполнения шва не подтверждено визуальной итерацией.

**Ключевые выводы (без выбора победителя — это задача Council):**

- Концепция 1 (Precision Wayfinding) сильнее всех в удобстве каталога/конверсии, но слабее всех в визуальной уникальности — риск, что решение не отвечает на запрос клиента про "премиальный индустриальный визуал".
- Концепция 2 (Blueprint Precision) — самый высокий визуальный потолок, но зависит от несуществующих пока фотоактивов, рискует "утечкой декора" в каталог (clip-path на 2000+ карточках) и тихо убирает существующее video-поведение VehicleShowcase без явного согласия пользователя.
- Концепция 3 (Drawing Sheet System) — самая сбалансированная и рискоосознанная: явно и по номеру пункта отклоняет объединение Hero/VehicleShowcase видео, заменяет второй imagery-блок функциональной "полосой совместимости" с реальными ссылками.
- Концепция 4 (Schematic Spine) — самая безопасная технически и по производительности, но наиболее консервативна визуально — риск не оправдать ожидания клиента от редизайна.
- Все четыре концепции независимо отклонили объединение Hero- и VehicleShowcase-видео в одну client-side сцену — это можно считать де-факто согласованным решением, а не открытым вопросом для Council.
- Концепции 2, 3, 4 находятся в одном понятийном поле ("инженерный чертёж/техпаспорт") с разной степенью риска/консервативности; концепция 1 — принципиально другая (IA/навигационная) ось. Итоговое решение, вероятно, потребует комбинации элементов минимум из двух концепций.
