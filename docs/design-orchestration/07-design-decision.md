# ADR: Редизайн главной страницы и навигационного каркаса AYPROM

## Status
Accepted (2026-07-28) — пользователь подтвердил оба открытых вопроса, план реализации разблокирован.

## Открытые вопросы — решены пользователем
1. **Объединение Hero+VehicleShowcase видео в одну client-сцену:** отказ council принят. Реализуется как две раздельные сцены с chip-лейблами/ссылками, без SVG-линий и state machine.
2. **Ambient-видео VehicleShowcase:** убрать. `VehicleShowcaseBackground.tsx` переходит на статичный poster/фон без `<video>`, ради производительности на среднем Android. Hero-видео остаётся единственным видео на странице — это фактически ужесточает non-negotiable "одно видео на Hero-сцену" до "одно видео на странице".

## Context
Council (`06-council-result.md`) на основе 4 независимых дизайн-концепций выбрал Precision Wayfinding (IA-каркас) как основу + точечный «инженерный datasheet»-слой из Schematic Spine, ограниченный Hero/VehicleShowcase/Footer. Lead Orchestrator (я) проверил решение против реального кода и non-negotiables перед принятием.

## Проверка Lead Orchestrator против реальности

1. **Не противоречит non-negotiables** — геометрия `VehicleShowcaseCard` не трогается, каталог не грузится целиком на фронт, никаких новых крупных зависимостей, реальные данные Supabase, App Router/npm/framer-motion сохраняются, WhatsApp-угол зарезервирован.
2. **Коррекция:** диагноз «второй imagery-блок без видимого контента» из baseline-аудита — по факту это `VehicleShowcaseSection`, чей грид карточек обёрнут в `<Reveal>`/`<StaggerGroup>` (framer-motion `whileInView`). Наиболее вероятная причина «невидимости» на baseline-скриншоте — automated full-page screenshot не триггерит `whileInView`-observer так же, как реальный скролл пользователя, а НЕ реальный производственный баг. **Council-рекомендация «добавить видимый чип-лейбл как диагностический шаг» принимается, но переформулирована**: сначала визуально проверить секцию реальным скроллом (не full-page screenshot) прежде чем тратить работу на диагностику несуществующего бага.
3. **Принимаю единогласный отказ от объединения Hero+VehicleShowcase видео в одну client-сцену** — все 4 независимые концепции и все 3 члена совета пришли к этому выводу независимо, это самый сильный сигнал согласия во всём процессе. Технически это отказ от исходной идеи, с которой начался разговор про Чекпоинты 1-3 — требует явного решения пользователя (см. ниже), Council не может принять это решение за него.
4. **Не принимаю пока** council-рекомендацию «оставить решение по ambient-видео VehicleShowcase открытым» как финальное — это блокирует Phase 2, нужен явный ответ пользователя.

## Decision
Принять направление Council как основу: IA-каркас (breadcrumbs, единый поиск, facet-чипы, «Похожие товары») + ограниченный инженерный слой (Geist Mono, hairline/скобки только на Hero, footer title-block), без HUD/spine/clip-path/leader-line в v1. Полный список — см. `06-council-result.md` разделы 5-14.

## Preserved functionality
Все текущие URL, поиск `/catalog?q=`, геометрия `VehicleShowcaseCard`, backend-пагинация, RLS, framer-motion как единственная анимационная библиотека.

## Rejected alternatives
HUD-слой, coordinate ruler, spine, clip-path на карточках, SVG leader-line в v1, объединение видео Hero+VehicleShowcase в одну сцену — обоснование см. `06-council-result.md` §4.

## Technical consequences
2 новых client-границы (`FilterSheet`, `HeaderSearchTrigger`), остальное — server components. Geist Mono через `next/font`, без новых внешних зависимостей.

## UX consequences
Каталог/поиск получают сквозную навигацию (breadcrumbs+facet-чипы+похожие товары) — по матрице это самый весомый критерий (20%) и самый большой разрыв в оценках (92 vs 55-68).

## Performance budget
Одно фоновое видео на Hero (как сейчас); судьба второго ambient-видео VehicleShowcase — открытый вопрос №2 ниже. Никаких новых тяжёлых ассетов/библиотек.

## Accessibility requirements
См. `06-council-result.md` §13 — WCAG AA, aria-live/expanded/current, focus-visible, prefers-reduced-motion на каждом новом анимированном элементе.

## Mobile principles
Отдельная композиция (не сжатие desktop): FilterSheet вместо sidebar, breadcrumbs сворачиваются, VehicleShowcase остаётся 2 колонки, горизонтальная «линейка» вместо вертикального шва.

## Risks
1. Визуальный потолок IA-каркаса может не оправдать ожидания клиента от «премиального визуала» — не подтверждено без визуальной итерации (preview запрещён без разрешения).
2. Качество фотоактивов техники — общий незакрытый риск, отдельный трек вне этого решения.
3. Facet-counts могут потребовать нового агрегирующего RPC — не блокирует v1, но добавляет будущую задачу.

## Rollback strategy
Коммит `04afd56 "До редизайна"` — уже существующая точка отката до начала любых изменений. Каждая фаза (Phase 0-3) — отдельный коммит с проходящей сборкой, откат по фазам через `git revert` при необходимости.
