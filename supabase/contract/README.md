# «Расширить → переключить → сузить» для каталога

Пока живой сайт на Vercel остаётся запасным (минимум 30 дней после переезда), база должна обслуживать **оба** сайта:

| Сайт | Как читает каталог |
|---|---|
| Vercel (старый) | напрямую из таблиц ключом `anon`; поиск `search_catalog_products` **без** указания публикации |
| Cloudflare (новый, статический) | только из запечатанной публикации; поиск **с** `publication_id` и `publication_capability` |

## Состояния

1. **Расширение (`supabase/migrations/`, применяется к боевой базе до переезда).**
   Последняя миграция `20261012090000_expand_contract_bridge.sql` возвращает `anon`/`authenticated` чтение 11 таблиц каталога
   (ровно как в `20260827120000_least_privilege_client_roles`) и учит `search_catalog_products`: вызов без публикации идёт по живым
   таблицам, вызов с публикацией — по запечатанной копии.
2. **Сужение (`supabase/contract/20261201000000_catalog_source_lockdown.sql`, НЕ применяется до отключения Vercel).**
   Снова закрывает чтение таблиц и убирает «живой» путь поиска. Применять так: после отключения Vercel и свежей резервной копии
   скопировать файл в `supabase/migrations/` и выполнить `supabase db push --include-all`.

`supabase/schemas/` описывает **конечное** (суженное) состояние, а мост — временная надстройка над ним. Поэтому, пока мост не снят,
`supabase db diff` для генерации миграций не использовать (проверка `npm run schema:declarative` сверяет только имена объектов и проходит).

## Тесты

`node scripts/dev/db-test-states.mjs` сбрасывает локальную базу и прогоняет тесты в обоих состояниях:

* расширение: `supabase/tests/database/*` (включая `expand_contract_bridge.test.sql`);
* сужение: те же тесты без теста моста + строгие тесты `supabase/contract/tests/*` (закрытые таблицы, поиск только по публикации);
* тест моста обязан упасть после сужения: так проверяется, что он не «слепой».

`node scripts/dev/migration-compat.mjs` проверяет на локальной базе, что **код `main`** (Vercel) продолжает работать на текущей схеме
(27 вызовов: публичные страницы, поиск, админские записи, вход, импорт). Эталон — схема `main`: 27/27.
